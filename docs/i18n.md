# Internationalisation

English and Italian, with **typed keys**. Files: `src/lib/i18n/index.ts`, `en.ts`, `it.ts`.

## How it works

`src/lib/i18n/index.ts` initialises i18next once, as a side effect of being imported (the root layout imports it first):

- Resources are bundled (`en`, `it`), so initialisation is **synchronous** (`initAsync: false`, no Suspense): no flash of untranslated text.
- The language is the stored choice, else the device language (`expo-localization`, first locale's language code) when it is one of ours, else English (`fallbackLng: "en"`).
- `interpolation.escapeValue` is `false` (React already escapes).

### Language preference

`LanguagePreference` is `system` or a `LanguageCode`.

| Export                           | Meaning                                                                                                                  |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `LANGUAGES`                      | `{ en: { label: "English" }, it: { label: "Italiano" } }`: labels are shown in their own language and are not translated |
| `LANGUAGE_CODES`, `LanguageCode` | The shipped codes                                                                                                        |
| `setLanguagePreference(value)`   | Stores it (`language` setting), calls `changeLanguage`, notifies subscribers; every `t()` re-renders                     |
| `useLanguagePreference()`        | The saved choice (`system` or a code), re-renders on change                                                              |
| `i18n`                           | The i18next instance, for code outside React (`i18n.t("errors.generic")`)                                                |

## Using strings

```tsx
const { t } = useTranslation();
<Text>{t("demo.homeTitle")}</Text>
<Text>{t("menu.label", { title: item.title })}</Text>      // "Actions for {{title}}"
```

- Every user-visible text goes through `t()`, including `accessibilityLabel`s, placeholders, toast messages and dialog texts. No hardcoded strings in components.
- Keys are typed against the English file (`CustomTypeOptions`), so a typo or a missing key fails `pnpm typecheck`.
- Outside React (a plain module), use `i18n.t(...)`.
- Dates and numbers use `Intl` with `i18n.language` (the calendar does).

Rules:

- Do not translate server error messages; show them as received. The app's own errors (network, timeout, 401, ...) are translated.
- Group names mirror screens (`auth`, `settings`, `account`, ...), with shared text in `common`, `validation` and `errors`.
- A dynamic key must be built from known literals, such as ``t(`theme.${preference}`)`` where `preference` is `"system" | "light" | "dark"`.

| Group                                                | Content                                                                                                                      |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `common`                                             | Shared words: back, cancel, confirm, delete, skip, next, getStarted, tryAgain, pleaseWait, undo, loading, edit, save, goBack |
| `tabs`                                               | Tab labels and the quick-add label                                                                                           |
| `demo`, `showcase`                                   | The demo screens and the Components tab. **Delete with the demo**                                                            |
| `menu`                                               | Context menu: close, "Actions for {{title}}"                                                                                 |
| `permission`                                         | Permission sheet and row texts, status labels                                                                                |
| `settings`, `theme`, `accent`, `language`            | Settings and picker screens                                                                                                  |
| `account`, `auth`, `changePassword`, `deleteAccount` | Sign-in and account screens                                                                                                  |
| `onboarding`, `launch`                               | First launch and the launch screen                                                                                           |
| `dataError`, `offline`, `calendar`                   | Component texts                                                                                                              |

| `errors`                                             | API and generic errors, the not-found screen, the error boundary                                                             |

## Writing strings

- One key per whole sentence. **Do not build sentences from several keys**: word order differs between languages.
- Use `{{name}}` for values. Keep strings short and free of formatting.
- Counts: i18next plural suffixes (`key_one`, `key_other`) and `{ count }` when you need plurals.
- Sentence case. Buttons start with a verb.

## Adding a string

1. Add the key to `en.ts` (the source of truth).
2. Add the same key to `it.ts` and every other language file. `it.ts` is typed `Translation`, so a missing or extra key is a type error.
3. Use `t("group.key")`.

## Adding a language

1. Create `src/lib/i18n/<code>.ts` exporting an object of type `Translation` with every key.
2. In `index.ts`: import it, add it to `LANGUAGES` (`label` in its own language) and to the `resources` map.
3. Nothing else: the language picker and the device-language detection read `LANGUAGES`.
4. If the language is right to left, test the layouts (use logical start and end properties).

Example (Spanish):

```ts
// src/lib/i18n/es.ts
import type { Translation } from "./en";
export const es: Translation = {/* every key of en.ts, translated */};

// src/lib/i18n/index.ts
export const LANGUAGES = {
  en: { label: "English" },
  it: { label: "Italiano" },
  es: { label: "Español" },
} as const;
// resources: { en: { translation: en }, it: { translation: it }, es: { translation: es } }
```

The device language is matched by its two-letter code; anything unsupported falls back to English.

## Native pieces

- System dialogs (permission prompts) use the device language automatically.
- The app name on the home screen is not translated by this setup. Per-language names need `locales` entries in `app.config.ts` and a strings file per language; add them when you localise the store listing.
- The Android notification channel name comes from `t("permission.channel")` when the permission is requested.
- Right-to-left languages need extra layout work and an app restart when the direction changes; this shell does not set that up (it does use logical start and end properties where it can).

## Testing

Switch the language in Settings and walk the screens; check long Italian strings in titles, buttons and rows (the header wraps titles, rows wrap descriptions). Typecheck proves the key sets match.
